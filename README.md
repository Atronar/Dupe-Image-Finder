Dupe Image Finder
==================

**Dupe Image Finder** — библиотека для сравнения изображений по набору
векторов: средней яркости, контрасту, текстуре и цвету. Алгоритм основан
на анализе изображения и его четвертей (логика
[этого кода на Ruby](https://gist.github.com/liamwhite/b023cdba4738e911293a8c610b98f987)).

Требования
----------

* Python >= 3.10;
* NumPy;
* OpenCV, Pillow, pyvips и CuPy — необязательные декодеры и ускорения.
  Для чтения изображений нужен хотя бы один декодер.

Установка
---------

```bash
pip install .
pip install ".[opencv]"   # быстрый CPU-декодер
pip install ".[pillow]"   # альтернативный декодер
pip install ".[vips]"     # libvips
pip install ".[gpu]"      # CuPy для NVIDIA GPU
pip install ".[dev]"      # pytest и декодеры для тестов
```

CuPy должен соответствовать установленной версии CUDA. Если CUDA
недоступна, библиотека автоматически продолжит работу на CPU.

Быстрый старт
-------------

```python
import duplicatefinder as df

vectors = df.intensities("image.jpg")
print(len(vectors))       # число характеристик
print(vectors[0].shape)   # размерность вектора яркости
```

`intensities()` возвращает четыре вектора. При `partition_level=2`
первые три имеют длину `1² + 2² = 5`: это средняя яркость, контраст и
текстура. Четвёртый — цветовой вектор длины `5 * 5 = 25`:

* 5 значений нейтральной опоры;
* 5 положительных и 5 отрицательных значений `a`;
* 5 положительных и 5 отрицательных значений `b`.

Все значения цветового вектора лежат в `0…1`. Нейтральная опора не
даёт почти серым изображениям и мелким цветным меткам давать большое
расстояние. Для серых изображений цветовые интегралы не считаются.

Цветовой вектор сравнивается обычной функцией `similarity()` наравне
с остальными. `similarity_images()` по-прежнему просто сравнивает все
векторы одной и той же функцией.

Основные параметры
------------------

* `partition_level` — уровень разбиения изображения; размерность каждого
  вектора равна `sum(n²)` для `n` от 1 до `partition_level`;
* `blur_ksize` — размер ядра размытия Гаусса; `(0, 0)` отключает размытие;
* `use_gpu` — попытаться использовать CuPy; при отсутствии CUDA
  вычисления автоматически выполняются на CPU;
* `use_threads` — параллельный расчёт характеристик одного изображения.
  По умолчанию отключён: после векторизации уровней потоки для одного
  изображения дают только накладные расходы. Для набора изображений
  используйте `intensities_iter()`.

Приоритет бэкендов
------------------

Для загрузки, размытия и интегральных изображений выбирается самый
быстрый доступный вариант:

1. CuPy (GPU);
2. OpenCV;
3. pyvips;
4. собственная реализация на NumPy.

Если не установлен ни один декодер, библиотека всё равно импортируется,
но для чтения изображений потребуется OpenCV, Pillow или pyvips.

Чистый путь Pillow + NumPy остаётся полностью рабочим. В нём обратная
гамма-коррекция sRGB выполняется по таблице, а не степенной функцией
на каждом пикселе: это примерно вдвое ускоряет расчёт Lab без заметного
изменения цветового вектора.

------

#### intensities

**intensities(image_path: str|Path|BinaryIO, partition_level=2,
blur_ksize=(3, 3), use_threads=False, use_gpu=True) -> list[array]**<br>
Главная функция модуля. Возвращает список векторов, соответствующих
изображению.

Изображение приводится к BGR `float32` в диапазоне `0…255`. Учитывается
EXIF-ориентация, 16-битные изображения нормализуются, альфа-канал
композитируется на белом фоне. Для GIF читается первый кадр.

#### intensities_iter

**intensities_iter(image_list: Iterable[str|Path|BinaryIO], **kwargs) ->
Generator[list[array]]**<br>
Обёртка над [intensities](#intensities) для набора файлов. Изображения
обрабатываются параллельно, порядок результатов сохраняется. Подходит
для построения базы векторов с последующим поиском дубликатов.

#### similarity

**similarity(vector1: array, vector2: array) -> float ∈ [0; 1]**<br>
Уровень похожести между двумя векторами.<br>
0 — векторы идентичны<br>
1 — векторы максимально разные

Векторы должны быть одномерными, непустыми и конечными.
Цветовой вектор сравнивается этой же функцией: он приведён к общей
шкале `0…1`.

#### is_similar

**is_similar(vector1: array, vector2: array, threshold: float=0.1) -> bool**<br>
Возвращает *True*, если векторы похожи. Порог должен быть конечным
неотрицательным числом.

#### similarity_images

**similarity_images(image1: str|Path|BinaryIO, image2: str|Path|BinaryIO)
-> list[float]**<br>
Сравнивает изображения и возвращает список расстояний: яркость,
контраст, текстура и цвет. Последний элемент — цветовое расстояние.

#### is_similar_images

**is_similar_images(image1: str|Path|BinaryIO, image2: str|Path|BinaryIO,
threshold: float=0.1) -> bool**<br>
Возвращает *True*, если изображения похожи по всем характеристикам.

#### Метаданные для кэша

**FEATURE_VERSION: int**, **FEATURE_NAMES: tuple[str, ...]**<br>
Версия определения характеристик и стабильные машинные имена в порядке
`intensities()`. Версия увеличивается, когда старые векторы становятся
несравнимыми с новыми: при изменении формата, нормировки или констант
цветовой характеристики.

**feature_lengths(partition_level=2) -> tuple[int, int, int, int]**<br>
Длины векторов яркости, контраста, текстуры и цвета. Первые три равны
числу регионов `N`, цветовой вектор занимает `5N`.

**config_hash(partition_level=2, blur_ksize=(3, 3)) -> str**<br>
Стабильный хеш настроек, влияющих на значения векторов. Вместе с
`FEATURE_VERSION`, размером файла и временем изменения подходит как ключ
кэша. Небольшие различия между бэкендами в хеш не входят.

Библиотека не хранит базу векторов: для динамического каталога приложение
может использовать SQLite и пересчитывать векторы только при изменении
размера, времени модификации, `FEATURE_VERSION` или `config_hash`.

Тесты и бенчмарк
----------------

```bash
pip install -r requirements-dev.txt
python -m pytest -q --disable-warnings
python benchmarks/benchmark.py
python benchmarks/color_benchmark.py
```

Первый бенчмарк печатает медианное время загрузки, интегральных
изображений, размытия, расчёта характеристик на разных уровнях разбиения
и сравнения векторов. Второй сравнивает бэкенды цветового конвейера:
декодирование, размытие, BGR → Lab, цветовую долю, интегральные
изображения и сборку цветового вектора.
